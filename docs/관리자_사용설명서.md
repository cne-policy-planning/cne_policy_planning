# 관리자 사용설명서

교무행정 통합검색에 자료를 등록하고 사이트에 반영하는 방법입니다. 프로그래밍 지식 없이 순서대로 따라 하면 됩니다.

- 저장소: `cne_policy_planning`
- 공개 사이트: `https://(GitHub 아이디).github.io/cne_policy_planning/`
- 관리자 도구: `https://(GitHub 아이디).github.io/cne_policy_planning/admin/`

---

## 0. 처음 한 번만: 준비 (약 30분)

### ① 저장소 만들기 *(완료)*
GitHub에 `cne_policy_planning` 저장소(Public)를 만들고 README 파일을 하나 만들어 둡니다.

### ② 사이트 켜기 *(완료)*
저장소 **Settings → Pages**에서 Branch를 **main / (root)**로 지정하고 Save를 누릅니다.

### ③ 프로그램 파일 올리기
1. 받은 압축 파일 `cne_policy_planning_프로그램.zip`을 풉니다.
2. 압축을 푼 폴더를 열고, **안에 있는 파일과 폴더 전체를 선택**(Ctrl+A)합니다.
   - 폴더 자체를 끌어다 놓으면 한 단계 아래에 들어가 사이트가 열리지 않습니다. 반드시 **안의 내용**을 선택하세요.
3. GitHub 저장소 첫 화면 → **Add file → Upload files** → 선택한 항목을 끌어다 놓습니다.
4. 업로드가 끝나면 아래 **Commit changes**를 누릅니다.
5. 1~2분 뒤 관리자 도구 주소(`…/cne_policy_planning/admin/`)가 열리는지 확인합니다.

### ④ 출입증(액세스 토큰) 발급
GitHub 화면은 영어입니다. 아래 순서대로 누르세요.

1. GitHub 오른쪽 위 **프로필 사진 → Settings**
2. 왼쪽 메뉴 맨 아래 **Developer settings**
3. **Personal access tokens → Fine-grained tokens → Generate new token**
4. 칸을 이렇게 채웁니다.
   - **Token name**: `통합검색 관리자 도구` (아무 이름이나 가능)
   - **Expiration**: 원하는 기간. 1년을 권합니다(**Custom**을 고르고 1년 뒤 날짜 선택). **이 날짜를 적어 두세요.**
   - **Repository access**: **Only select repositories** → `cne_policy_planning` 하나만 선택
   - **Permissions → Repository permissions → Contents**: **Read and write**
     (Metadata는 자동으로 Read-only가 됩니다. 다른 권한은 건드리지 않습니다.)
5. 맨 아래 **Generate token** → 나타난 `github_pat_…` 문자열을 **복사**합니다.
   - 이 화면을 벗어나면 다시 볼 수 없습니다. 바로 ⑤로 넘어가세요.

### ⑤ 관리자 도구에 연결
1. 관리자 도구(`…/cne_policy_planning/admin/`)를 엽니다. **저장소** 칸은 자동으로 채워집니다.
2. **출입증** 칸에 복사한 문자열을 붙여 넣습니다.
3. **출입증 만료일**에 ④에서 정한 날짜를 넣습니다.
4. **GitHub 연결**을 누릅니다. "연결되었습니다"가 나오면 완료입니다.
5. 오른쪽 위 **🔑 출입증 D-○○** → **📅 캘린더에 알림 추가**를 누르면 일정 파일이 받아집니다. 열어서 휴대폰·PC 캘린더에 추가하면 만료 30일·7일·1일 전과 당일 오전 9시에 알림이 옵니다.

> **출입증 관리**
> - 출입증은 이 PC의 브라우저에만 보관되고 공개 사이트 파일에는 들어가지 않습니다.
> - 공용 PC라면 연결할 때 "이 PC에 출입증 기억하기"를 끄세요. 창을 닫으면 지워집니다.
> - 다른 사람에게 출입증을 알려 주지 마세요. 출입증이 있으면 사이트 자료를 고칠 수 있습니다. 유출이 의심되면 GitHub 같은 화면에서 그 출입증을 **Delete**하고 새로 발급하세요.

## 1. 관리자 도구 열기

웨일·크롬·엣지에서 `https://(아이디).github.io/cne_policy_planning/admin/`을 엽니다(즐겨찾기 추천).
연결된 PC라면 열자마자 GitHub에서 최신 자료를 자동으로 불러옵니다.

> 오른쪽 위 상태 표시
> - **사이트와 같음**: 고친 것이 없음
> - **반영 안 된 변경 있음**: 고친 내용이 아직 사이트에 올라가지 않음
> - **반영 완료 · 사이트 갱신 1~2분**: 올렸고, 사이트에 곧 나타남
> - **🔑 출입증 D-○○**: 출입증 만료까지 남은 날(누르면 연결 관리)

PDF·한글 파일은 **내 PC 브라우저 안에서만** 처리되고 어디에도 전송되지 않습니다. PDF·HWPX 읽기 도구가 프로그램 안에 들어 있어 학교망에서 외부 사이트가 막혀 있어도 동작합니다.

## 2. 자료 등록 (① 자료 등록 탭)

1. **공통 정보**를 고릅니다: 학교급(여러 개 가능), 업무 분류, 연도, 원 출처.
2. 파일을 끌어다 놓습니다. 여러 개를 한꺼번에 넣어도 됩니다.
   - **PDF·HWPX**: 본문을 읽어 목차대로 업무를 나눕니다.
   - **HWP·엑셀 등**: "링크형 자료"로 등록됩니다. 자료명·검색어로만 검색됩니다.
3. 파일마다 **자료명**과 **웍스 링크**(원본 파일의 웍스 공유 링크)를 넣습니다. 나중에 넣어도 됩니다.
4. **분석 시작** → 결과(예: `37쪽 · 업무 27개 · 목차 인식 · 서식 255개`)를 확인합니다.
5. **목록에 추가**를 누릅니다. 아직 사이트에는 반영되지 않았습니다(5장에서 반영).

> 이미 있는 자료의 새 판이면 새로 등록하지 말고 **자료 관리 → 파일 교체**를 쓰세요. 검색어와 서식 쪽 정보가 유지됩니다.

---

## 3. 자료 다듬기 (② 자료 관리 탭)

왼쪽 목록에서 자료를 고르면 오른쪽에서 고칠 수 있습니다. 칸을 고치고 다른 곳을 누르면 바로 반영됩니다.

### 업무 검색어 (가장 중요)
선생님들이 실제로 쓰는 말과 문서 표현이 다를 때 넣습니다.
- 예: 「현장체험학습 운영」 업무에 `소풍, 사전답사, 현장학습`
- 이렇게 하면 "소풍"으로 검색해도 이 업무가 위쪽에 나옵니다.
- 업무 목록의 **보기**를 누르면 그 업무의 본문과 서식을 확인할 수 있습니다.

### 업무 구간 고치기
- 업무명·상위 분류·쪽 범위를 직접 고칠 수 있습니다. 쪽 번호는 **PDF 쪽**(파일에서 몇 번째 장인지)입니다.
- 목차를 못 찾은 문서는 업무가 쪽 단위로 나뉘므로, 업무명을 고치거나 **+ 업무 추가**로 범위를 지정하세요.
- **자동 분할 다시**: 처음 상태로 다시 나눕니다(업무명이 같은 업무의 검색어는 유지).

### 확인 필요 표시
목록의 **확인**·**오류** 표시는 웍스 링크 없음, 학교급 없음 같은 빠진 정보입니다. "확인 필요 자료만"으로 모아 볼 수 있습니다.

## 4. 서식 모음 만들기

PDF 안의 서식 링크(예: 유치원 도움자료 255개)를 **한글 파일 하나**로 묶어 웍스에 올리고, 사용자에게는 "서식 모음 → 183번 서식 · 198쪽"처럼 위치를 안내합니다.

1. 자료 관리 → **서식** 카드 → **① 서식 내려받기 목록 만들기**
   - 번호·권장 파일명이 붙은 HTML 파일이 저장됩니다. 브라우저로 열어 순서대로 **내려받기**를 누르고 권장 파일명(예: `183_현장체험학습 계획서(예시)`)으로 저장합니다.
2. 한글에서 새 문서 → **입력 → 문서 끼워 넣기**로 1번부터 순서대로 넣습니다. 서식 사이에는 **쪽 나누기(Ctrl+Enter)**를 넣습니다.
   - 길라잡이처럼 큰 PDF 자료는 빼도 됩니다. 뺀 서식은 쪽이 비어 있게 됩니다.
3. 완성한 파일을 웍스에 올리고, 공유 링크를 **서식 모음 웍스 링크**에 넣습니다.
4. 같은 문서를 한글에서 **PDF로도 저장** → **② 서식 모음에서 쪽 찾기**에 넣으면 각 서식의 쪽 번호가 자동으로 채워집니다. 못 찾은 서식은 목록에서 쪽을 직접 입력합니다.

## 5. 점검·반영 (③ 점검·반영 탭)

1. **점검 실행**: 빠진 정보와 바뀔 파일 수를 보여줍니다. 빨간 **오류**가 있으면 고쳐야 반영됩니다(예: 학교급 없음).
2. **변경 내용 메모**에 한 줄 적습니다(예: `유치원 자료 3건 등록`). 비워 두면 자동으로 적힙니다.
3. **사이트에 반영**을 누릅니다. 바뀐 파일만 GitHub에 올라갑니다.
4. 1~2분 뒤 공개 사이트에서 검색됩니다.

### 이럴 땐
- **"출입증이 올바르지 않거나 만료되었습니다"**: 0장 ④~⑤처럼 새 출입증을 발급해 🔑 버튼 → **새 출입증으로 바꾸기**에 넣습니다.
- **"쓰기 권한이 없습니다"**: 출입증의 Contents 권한이 **Read and write**인지, 저장소로 `cne_policy_planning`을 골랐는지 확인합니다.
- **"다른 곳에서 바뀌었습니다"**: 다른 PC에서 반영했거나 GitHub에서 자료 파일을 직접 고친 경우입니다. 덮어쓰지 않도록 멈춘 것이니, 새로고침해 최신 자료를 불러온 뒤 다시 작업하세요.
- **반영하지 않고 창을 닫았다면**: 다음에 열 때 "반영하지 않은 작업이 있습니다"가 나옵니다. **이어서 하기**를 누르면 됩니다(같은 PC·같은 브라우저에서만).

### 예비 방법 (GitHub 연결이 안 될 때)
③ 탭 아래 **예비 방법**에서 저장소 폴더 저장 또는 ZIP 내보내기를 쓸 수 있습니다. 이 경우 GitHub Desktop이나 GitHub 웹 화면(Add file → Upload files)으로 직접 올려야 합니다.

## 6. 자료 교체·삭제

- **파일 교체**: 새 판 파일을 넣으면 분석 결과를 보여주고, **교체 적용**을 눌러야 바뀝니다. 분석에 실패하면 기존 자료가 그대로 남습니다. 웍스의 원본 파일도 새 판으로 바꾸고, 서식이 바뀌었으면 서식 모음도 다시 만드세요.
- **자료 삭제**: 목록과 모든 색인에서 지웁니다. 반영해야 사이트에서 사라집니다. 웍스의 원본은 지워지지 않습니다.

만료 30일·7일·1일 전에 관리자 도구를 열면 알림창이 뜨고, 위쪽에 경고 줄이 표시됩니다. 캘린더 알림과 GitHub 안내 메일도 옵니다.

1. 0장 ④처럼 새 출입증을 발급합니다.
2. 관리자 도구 오른쪽 위 **🔑** → **새 출입증으로 바꾸기**에 붙여 넣고, 새 만료일을 넣고 → **바꾸고 연결 확인**
3. **📅 캘린더에 알림 추가**로 새 만료일 알림을 다시 등록합니다.
4. (선택) GitHub의 Fine-grained tokens 목록에서 예전 출입증을 **Delete**합니다.

## 8. 알아 둘 점

- 반영하지 않은 작업은 이 PC의 브라우저에만 임시 보관됩니다. 다른 PC에서는 보이지 않으니, 작업을 마치면 꼭 반영하세요.
- `data` 폴더의 파일은 GitHub에서 직접 고치지 마세요. 항상 관리자 도구로 고칩니다.
- **공개 사이트의 데이터는 누구나 내려받을 수 있습니다.** 개인정보가 들어 있는 자료는 올리지 마세요.
- 지원하지 않는 것: 스캔 PDF 글자 인식(OCR), HWP·엑셀 본문 검색, HWPX 인쇄 쪽수, 웍스 문서의 특정 쪽 바로 열기.
